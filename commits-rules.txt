CONVENTIONAL COMMITS — ПРАВИЛА ОФОРМЛЕНИЯ КОММИТОВ

Общий формат:
<type>[optional scope]: <description>

Основные типы:
feat — добавление новой функциональности
fix — исправление ошибки
docs — изменение документации
style — изменения форматирования без изменения логики
refactor — изменение структуры кода без изменения поведения
test — добавление или изменение тестов
chore — служебные задачи и обслуживание проекта

Правила оформления:
1. Указывай тип изменения в начале сообщения.
2. После типа ставь двоеточие и пробел.
3. Пиши краткое и понятное описание изменения.
4. При необходимости указывай область изменения в скобках.
5. Для несовместимых изменений используй BREAKING CHANGE в описании.

Примеры:
feat: add login form
fix: correct button color
docs: update installation guide
docs(git): add commands list
